# ACore2 Network Probe v0.1

Отдельная диагностика для проверки сетевых данных сапфира/эфира на AION2 Global EU/NA. Эта программа записывает наблюдения; управление GatherScanner по сети ещё не подключено.

## Как запустить

1. Нужны установленный Python 3 (как для GatherScanner), Npcap и отдельный [Cube.Radar.exe](https://github.com/dr89mh/aion2-cube-radar/releases/latest). Сама утилита их не устанавливает и ничего автоматически не скачивает. Если AionCore уже работает, захват Npcap, вероятно, настроен, но это не гарантирует доступ другому приложению.
2. Остановите сканер сбора, чтобы запись отражала ваши ручные действия. Запустите `START_RECORDING.bat` и выберите файл **Cube.Radar.exe**. Альтернатива: положите Cube.Radar.exe рядом с probe.py. Lua и настройки бота не меняются.
3. Запись длится 180 секунд. Переключитесь в игру, выберите сапфир вручную и нажмите **Ctrl+Alt+F5**. Один раз F запускает подход. Когда появилась нижняя плашка, отметьте **Ctrl+Alt+F7**; закончилась одна попытка — **Ctrl+Alt+F8**; ресурс полностью исчез — **Ctrl+Alt+F9**. Затем эфир, его выбор — **Ctrl+Alt+F6**, начало/попытка/исчезновение отмечаются так же. Если двух ресурсов за три минуты нет, достаточно одного; следующую запись можно сделать отдельно.
4. Эти сочетания ставят временные отметки в записи. Они не выбирают ресурс и не выполняют сбор. Если сочетание занято другим приложением, CubeRadar сообщает об ошибке регистрации; тогда отметки не гарантированы. В консоли CubeRadar можно также ввести точную подпись `sapphire_selected`, `aether_selected`, `first_gather`, `attempt_completed` или `resource_depleted` и Enter.
5. После окончания рядом с записью появится **probe_report.zip**. Для первого анализа нужен именно он. Путь выводится в консоли и находится под `captures` рядом с утилитой.

## Что попадёт в отчёт

Только `report.json` и `object_events.jsonl`: количество типов сообщений, ID/координаты объектов, их появление/удаление/взаимодействия и отметки. Известная схема ресурса Global отмечается как **кандидат**, с именем из MIT-каталога и возможным использованным счётчиком. Это ещё не проверенная идентичность ресурса на вашем клиенте, не доказательство начала своего сбора и не разрешение нажимать F.

Имена игроков, чат, IP, произвольные raw-поля и сырые пакеты в этот ZIP не включаются. Исходная запись CubeRadar с `raw.pcapng`, `frames.jsonl`, `markers.jsonl` остаётся локально и может содержать личные данные. Её нельзя считать обезличенным отчётом. Ничего из записи автоматически не отправляется или не публикуется.

Ноль распознанных объектов означает, что поддержанная схема не обнаружена, а не что ресурсов нет. Разбор HP/FP и выбранной цели в эту первую диагностическую утилиту не включён: для них сначала нужна проверка источника и схемы.

## Повторный анализ и проверка

```
python probe.py --analyze "папка с frames.jsonl"
python probe.py --exe "C:\путь\Cube.Radar.exe" --seconds 300
python -m unittest test_probe -q
```

Проверки: 10 тестов прошли. Декодер проверен на опубликованном настоящем CubeRadar-фрагменте с двумя кубами, включая их XYZ и взаимодействия, и на искусственном профиле сапфира. Проверены границы/обрезанные данные, неизвестные типы, отсутствие сырых полей в ZIP, временные отметки и повторённые записи. Живой захват Windows/AION2 здесь не запускался; создание процесса и работа горячих клавиш проверены по исходникам CLI, а не на игровой машине.

Подробная проверка всех присланных репозиториев — в `NETWORK_REVIEW_RU.md`.
