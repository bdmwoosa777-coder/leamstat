# Проверка GatherScanner v0.12.2

Заключительный полный прогон: 1268 tests, OK, без пропусков.
Среда: Linux, Python 3.12, OpenCV, Tesseract rus/eng, lupa, тестовый HTTP,
синтетические сетевые состояния и тестовый Xbox. Новые сценарии — test_purpose.py.
Сценарии используют синтетические ID и изолированные образцы прежней публичной
тестовой базы; новый пользовательский журнал и полные кадры не публикуются.

Проверено:

- порядок main-loop: свежее распознавание при CRUISE, быстрые обработчики,
  переход к SEARCH, ресурсный обработчик, ACQUIRE_WAIT, следующий выбор;
  промежуточный END_AIR не отправляется;
- смена нулевого наклона во время обработки кадра не разрешает коррекцию
  по прежней системе отсчёта; номер калибровки меняется атомарно с её сбросом;
- позднее распознавание требует дополнительной текущей проверки, A не нажимается
  по одному старому результату; время воздушного захвата ограничено;
- найденная подпись отменяет отложенный повтор закрытия; native-закрытие не
  повторяется в анимации падения и не удерживает обработчик в бесконечном ожидании;
- простой таймер отсутствия добычи не даёт разрешения на подъём при отсутствии
  срабатывания отдельного terrain-watchdog; реальное длительное застревание
  по-прежнему может запустить спасение;
- новый удар прерывает RESCUE до следующего движения; источник, личность и
  выбранный ID продолжают проверяться; поиск может найти цель после четвёртой
  смены, неизвестный собственный ID не разрешает случайную атаку;
- лимит прежних эпизодов патруля не выключает его защиту, а ограничение при
  привязанном ресурсе сохраняется;
- неизменное расстояние до маркера не получает фиктивный свежий progress_at
  от visual-detour; заднее направление не заменяется передним;
- открытая связная, но шероховатая полоса сохраняет курс к ресурсу; локальная
  смена ID/оценок не меняет уже начатый короткий обход на противоположный;
- осмотр неудачного направления ограничен; близкий эфир начинает обзор раньше,
  а старый чрезмерный радиус всё ещё не останавливает подход слишком далеко;
- неудача карты до подтверждения даёт единственное закрытие, затем требует
  устойчивого игрового экрана; поиск продолжается без ложной отметки прибытия,
  таймер отсутствия добычи не сбрасывается, новый возврат получает cooldown;
- загрузка/неизвестный экран не дают ходьбу; ошибка после подтверждения не
  разрешает повторный свиток или предположение о состоявшемся телепорте;
- запрос RouteClient для thinking-модели содержит think=false и 192 токена;
  пустое содержимое ответа не принимается как маршрут и даёт метаданные ошибки;
- тесты прежнего native-транспорта сохраняют курсорные ограничения, отказ от
  RT/AOE, сброс ввода, guards карты и отсутствие конструкции GHubBridge
  при стандартном запуске. Прокрутка дополнительно требует позиции указателя
  и передаёт LT перед вертикальной осью, с конечным watchdog удержания.

Полный прогон включает прежние отрицательные проверки игроков, духов, ресурсов,
неоднозначного собственного ID, устаревших пакетов, незавершённого JSON,
загрузки, фокуса, CAPTCHA и смерти. Lua-протокол резервного режима также проверен.

Это офлайн-проверка управления, не запись живого прохождения. Реальные AION2,
ViGEmBus/Npcap в Windows, Ollama/Qwen и RTX 4080 вместе с игрой здесь не запущены.
Фактическая прокрутка LT в игре, качество распознавания новых кадров, скорость
маршрута и рост добычи требуют игрового запуска. Ошибки прежней модели по одному
сообщению JSON нельзя точно диагностировать без тела ответа; payload и более
информативный отказ проверены, успех реальной генерации не заявляется.

Публичные файлы: ZIP, README, VALIDATION, SHA256SUMS. Прежние ONNX, сетевой EXE,
Lua и requirements.txt проверяются побайтно против опубликованной v0.12.1.
