# ACore2 GatherScanner v0.9.1 — сбор по попыткам

## Что изменено

**В сетевом режиме больше нет фонового спама F.**

1. Один A выбирает ресурс; его тип/имя подтверждаются сетевым профилем. Если профиль появился до начала захвата и отсутствует, требуется свежая верхняя плашка ресурса с правильным именем, привязанная к выбранному ID после этого A. Известные NPC/игроки, чужой тип ресурса и старый кадр не подходят.
2. Один F запускает штатный подход/подлёт. Пока сбор не начался, повторного F нет. Единственное штатное исключение — подтверждённое открытие крыльев при застревании, отменившее старый автопуть.
3. Когда собственная попытка уже идёт, бот ничего не нажимает для её поддержания. После серверного окончания попытки отправляется **один F для следующей**. Пока новая попытка не началась, этот F не повторяется. Старое повторное сообщение об окончании предыдущей попытки не отменяет новую попытку.
4. Когда ресурс израсходован, крылья закрываются и начинается поиск следующей цели. При оставшихся попытках V не переключается. Движение дополнительно блокируется по самому сетевому факту собственного сбора, даже если внутренний режим потерял прежний признак.

Эта схема требует включённого **«Встроенная сеть: подтверждать сбор и удары (Npcap)»**. Старый визуальный резервный режим без сети не использует новый счётчик попыток.

Выбор ресурса больше не запускает длинный поиск OCR в основном цикле: текущая подпись отслеживается локально по рисунку её букв. Полный OCR работает отдельно и имеет ограничение времени. Клик производится в хитбокс прямо под подтверждённой подписью. Поиск синего объекта под сапфиром убран: флаг/дух/эффект не подтверждают ресурс.

Моб, умерший во время подготовки повторного удара, теперь считается успешно убитым; ресурс после этого сохраняется для возврата. Пауза после неудачной проверки одного агрессора не скрывает удар другого. Журнал отдельно отмечает разбор входящего удара и возраст захваченного пакета при начале защиты. Это позволяет измерить задержку внутри программы, но не задержку до прихода пакета из игры.

Пробный выход из упора: камера вниз, короткий полёт **назад с подъёмом**, затем возврат взгляда. Длительность ограничена двумя секундами; по умолчанию 1,5 с. Это пробный манёвр, а не гарантированный набор заданного количества метров. При найденном наземном ресурсе пробный полёт сначала завершается; оставшиеся открытые крылья вне сбора закрываются перед свободным патрулём. Если наземный сбор уже начался с крыльями, V во время попытки не переключается.

## Приоритет эфира и энергия

Прежний флажок **«Только эфир»** переименован в **«Приоритет эфира; самоцветы при восстановлении энергии»**. Старое сохранённое `only_aether=true` автоматически включает новое поведение.

- Первый вылет при известной энергии — от **35%**. При достаточном запасе выбирается эфир; если его нет, бот патрулирует и ищет его.
- После перехода к эфиру при **20% и ниже** новые воздушные цели откладываются: бот ходит за наземными ресурсами и восстанавливает энергию.
- При восстановлении до **35%** эфир снова становится приоритетом. Уже начатый наземный сбор заканчивается полностью, смена приоритета его не срывает.
- Свежие числовые показатели энергии используются только две секунды после обновления. Затем остаются экранное измерение и ограниченная оценка восстановления; старое сетевое число не обнуляет её каждый цикл. Неизмеренная энергия не считается нулём: после защитной задержки разрешена одна проверочная попытка.

Пороги задаются в settings_gather.json: `aether_priority_low_percent` и `aether_priority_resume_percent`. Короткий спасательный полёт использует прежний отдельный бюджет энергии. Без флажка сохраняется смешанный сбор доступных ресурсов.

## Запуск

1. Закрой старую программу. Распакуй **весь архив в новую папку**. Не заменяй отдельные Python-файлы в старой папке. Можно перенести свои settings_gather.json и assets/world_map.
2. В игре оставь **режим управления 2**. В G HUB — профиль бота с GHUB_GATHER_SCANNER.lua, **ON-BOARD MEMORY MODE → OFF**. Lua в этом архиве побайтно прежний. Физический **G9** включает приёмник.
3. Запусти **START.bat**. Оставь встроенную сеть включённой, «Только наблюдение» выключенным. Для нового режима включи **«Приоритет эфира…»**.
4. **Ctrl+F8 — запуск, Ctrl+F9 — стоп**. При первом запуске лучше стоять на земле, без ручного взаимодействия.
5. В журнале будет «игровой поток подтверждён». Отдельные CubeRadar/Go/.NET не нужны; Npcap, Python, Tesseract и виртуальный Xbox остаются прежними.

Новая версия не должна писать F_ON в обычном сетевом сборе. После каждой непоследней попытки ожидается одна строка «Попытка завершена … один F для следующей». Команда TX обозначает отправку кадра Lua, а не подтверждённое выполнение игрой: обратного ACK у этого канала нет.

## Координаты, скалы и ИИ-зрение

Сохранены XYZ из поддерживаемых серверных сообщений, расчёт расстояния/разницы высот и статическая MIT-база 3 547 точек трёх карт (Verteron, Altgard, Abyss), плюс кибелиски. Потенциальная точка из базы не подтверждает живой ресурс. Покрытие не охватывает все карты. У слоя Abyss нет однозначного списка zone ID для автоматического выбора.

Собственная позиция не приходит непрерывно при каждом шаге. Точное наведение использует её только до возраста **0,8 с**, затем возвращается к миникарте/визуальной дистанции. «Состояние сети» показывает XYZ, источник и возраст. Энергия крыльев не считается высотой, чужие перемещения не подставляются вместо собственной позиции.

**По координатам персонажа и ресурса нельзя надёжно определить обрыв, море или проходимость между ними.** Нужна геометрия местности либо отдельная проверенная система зрения. В этой версии нет карты безопасных краёв, обхода моря или гарантии безопасного приземления. Дополнительное ИИ-зрение для скал/воды не подключено; это отдельная задача с игровыми примерами и проверкой скорости/ошибок модели.

Программный ПКМ на большой карте остаётся нерешённым. Защита реагирует на поддерживаемый сетевой Hit по своему персонажу; отдельный DoT и атаки только на духа без попадания по персонажу не добавлены.

## Если снова есть пауза или срыв

Нажми **«Состояние сети»**, затем **«Сохранить журнал…»**. Обычный gather.log лежит рядом с START.bat; для него есть кнопка «Папка журнала». Сохранять лучше сразу после проблемного эпизода до нового запуска. Папка network_diagnostics содержит состояние и ошибки модуля, а не полные пакеты. Ничего автоматически никуда не отправляется.
