# ACore2 GatherScanner v0.9.13 — свежая точка каждого повтора

Повтор A по ресурсу сохранён. В обычном сетевом режиме F для сбора
не используется. Первый клик выбирает ресурс, следующие клики по нему
запускают или поддерживают штатный подход и сбор.

## Изменения

В v0.9.12 один запрос поддержания при selected=0 мог передать два A:
сначала выбор, затем активацию. При отсутствии значка также допускалась
серия пробных кликов всё ниже подписи. Это разные экранные точки;
безопасность клика по ресурсу не доказывает попадание каждой из них.

Теперь собственный сбор получает один A за запрос с прежней паузой
около 0,8 с после доставки. Нулевой selected не добавляет скрытый второй
A. При отсутствии значка поддержание использует привязанную к свежей
подписи точку вместо серии четырёх смещений вниз. Для неё ещё раз снимается
кадр перед вводом. После последнего перемещения курсора выдерживаются
60 мс, затем свежий кадр должен подтвердить, что прежняя точка всё ещё
внутри значка. Курсор сразу перед A повторно не переставляется. При уходе
значка из точки запрос откладывается (CLICK_REANCHOR). Для точки под
подписью проверяется устойчивость положения и размера букв. Передача A разрешена и при attempt_active=True:
ожидание устаревшего active по-прежнему не блокирует повторы.

При следующем повторе точка снова проверяется; потерянная старая
координата не разрешает клик. Другой ненулевой выбранный ID, потеря сети,
фокуса или необходимость защиты прекращают серию из старого контекста.
Перед активацией после отдельного клика выбора в прежнем пути также
требуется обновить экранную точку. Новый подход до первого сбора сохраняет
поисковые точки для маленького эфира; как только подтверждается своё
начало, эта серия больше не продолжается.

Если эфир во время подлёта сильно сместился на экране, фоновый поток теперь
может снова найти его надпись по форме букв даже при сетевом active=True.
Раньше при этом состоянии оставались только локальный поиск и поиск
выбранной плашки, поэтому видимое слово могло ждать изменения ракурса.
Новый запасной проход не запускает общий OCR. При нескольких надписях
предпочитается ближайшая к предыдущей точке. Экранная надпись сама по себе
не доказывает ID: сетевые проверки выбранного ресурса сохраняются.

Во время удержания A проверяются фактический Alt, фокус и положение курсора
Windows. Если курсор ушёл от заданной точки, A отпускается и появляется
CURSOR_MISS. Это проверка курсора ОС, а не внутреннего хитбокса игры.

## Что установлено по последнему журналу

Первый собственный результат пришёл примерно через 7 секунд. Затем
следующие попытки закончились значительно быстрее. Во время этих срывов
журнал не зафиксировал ни F, ни левого стика. V передан после удаления
ресурса сервером. Между повторными A selected сбрасывался в ноль.

Это не доказывает, что A отменяет сбор. Без снимка точки нельзя проверить,
попал ли каждый повтор именно в ресурс, и нельзя подтвердить эквивалентность
всей последовательности ввода ручному клику. Исправление устраняет
обнаруженные серии и добавляет такую проверку. Живого запуска AION2 здесь нет.

## Диагностика точки

При поддержании сбора журнал пишет:

- CLICK_POINT — номер ввода, ID, точка, рамка подписи, рамка значка,
  selected/used/active перед A.
- CLICK_FEEDBACK — тот же номер, результат отправки, selected/used/active
  после A и последнее прочитанное положение курсора Windows.
- NET_COLLECTION — сетевой ordinal и причина удаления, если такое событие
  разобрано, дополнительно к счётчику и собственному результату.

При включённых debug_screenshots рядом со START.bat создаётся debug_clicks.
Там сохраняются только области вокруг этих точек с красным крестиком,
максимум 24 последних файла. Прежние снимки CLICK_WAIT остаются в debug_gather.
Записи и изображения локальные и автоматически никуда не отправляются.

INPUT_STATE продолжает читать ограниченный набор игровых клавиш примерно
раз в 25 мс во время своего сбора и при фокусе игры. Он не записывает текст,
не определяет источник нажатия и может пропустить короткий импульс.
PAD_REPORT показывает ненулевые отчёты стиков, с ограничением частоты.
Передача отчёта или A сама по себе не подтверждает выполнение игрой.

## Запуск

1. Закрой старую программу, распакуй весь архив в новую папку, запусти START.bat.
   INSTALL_ONCE.bat нужен только при отсутствии прежних зависимостей.
2. В игре — режим управления 2. В G HUB — прежний профиль, встроенная память OFF.
   Lua и сетевой EXE не менялись: Lua заменять не нужно.
3. Вернись в игру, нажми физическую G9 для приёмника. Ctrl+F8 — запуск,
   Ctrl+F9 — стоп. Встроенная сеть включена, «Только наблюдение» выключено.
4. После удаления старой папки заново укажи подходящий наклон камеры.
   В последнем запуске использовалось 940 мс, начальное значение архива — 770 мс.

Если отмена повторится, останови бота и сохрани gather.log вместе с папкой
debug_clicks этого запуска: журнал теперь можно сопоставить с местом ввода.
Полные кадры и захваты сети не входят в опубликованный архив.

## Сохранённое поведение

Собственный неполный ресурс не разрешает левый стик, END_AIR или отход
по одному лишь таймауту поиска точки. Поиск выбранной плашки работает
также при ещё неизвестном имени собственного ресурса. До первого сбора
освобождение при застревании остаётся доступным. Исчерпание/удаление ресурса
позволяет закрыть крылья. Перед правым стиком проверяется отпускание Alt;
автокалибровка во время сетевого сбора по умолчанию отключена.

Защита реагирует на подтверждённый сетевой удар, включая AoE моба,
целящегося в своего духа. После боя сохраняется ID прежнего ресурса.
«Приоритет эфира» сохраняет пороги энергии 20/35%. Сохранены поддерживаемые
XYZ и статическая MIT-база 3547 точек трёх карт; своя позиция используется
до возраста 0,8 с, затем — миникарта/визуальная дистанция. Непрерывное
сетевое позиционирование, геометрия скал и ИИ-зрение не добавлялись.

Результаты автоматических проверок и ограничения — в VALIDATION_RU.md.
