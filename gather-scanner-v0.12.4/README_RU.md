# GatherScanner v0.12.4 — шесть шагов вверх, свежий кадр и медленная прокрутка

Полный архив на основе v0.12.3. Остановите и закройте старый бот, распакуйте ВЕСЬ
ZIP в новую папку и запустите START.bat. В заголовке должно быть v0.12.4.
Рабочее общее окружение Python используется повторно, SETUP.bat повторно не нужен.
Модели, зависимости и драйверы прежние. Физический F710/приёмник отключите;
по умолчанию управление виртуальным Xbox, без G HUB/Lua/G9.
Старый settings_gather.json поверх нового не копируйте: в нём остаются прежние
радиус поиска и место возврата. Камера по умолчанию — 940 мс вниз после калибровки.
Ctrl+F8 — запуск/пауза; Ctrl+F9 — стоп.

## Поиск и подход

Первый дальний обзор теперь делает ШЕСТЬ коротких шагов вверх вместо четырёх,
затем выдерживает верхний ракурс, проверяет свежий кадр и возвращает наклон.
Длительность шага остаётся 69 мс (+15% к прежним 60 мс). Если подпись найдена
раньше, обзор прерывается для проверки и выбора ресурса.

Добавлена быстрая проверка глифа эфира по текущему кадру перед следующим шагом
камеры, а также периодически при подходе к близкой отметке. Она не ждёт завершения
фонового OCR. Полный кадр перед кликом всё равно проверяется заново.
Верхняя центральная маска теперь учитывает наличие ресурсной плашки: без неё
мировая подпись ниже верхней строки HUD доступна распознаванию. Сама плашка цели,
чат и миникарта по-прежнему не дают мировой точки клика.

Бот больше не начинает вертикальный обзор близкой отметки, когда камера смотрит
в противоположную сторону: сначала поворачивает обзор к ресурсу. Остановка или
поворот камеры для осмотра больше не превращаются локальным планировщиком в ходьбу.
Первый стационарный обзор начинается ближе (радиус 22 вместо 30 пикселей при базовой
ширине миникарты 313; это НЕ метры). Видимая подпись может быть выбрана и раньше.
Так меньше времени тратится на стояние далеко от ресурса.

## Куда возвращаться

По вашему выбору исходно указаны:

- Кибелиск: **Рабочий лагерь стального молота**.
- Номер в списке: **48**.

Поля «Кибелиск возврата» и «№ в списке» находятся в основном окне. При смене места
фарма впишите полное название и номер нужного кибелиска, затем «Сохранить настройки».
Изменение используется при следующем запуске возврата; уже начатый телепорт не
переименовывается посреди подтверждения. Галочкой можно отключить возврат через карту.
Приют теперь лишь пример из истории версий.

## Прокрутка и подтверждение

Нативная прокрутка списка уменьшена с 450 мс/0,80 до 90 мс/0,30. После каждого
шага стики и LT отпускаются, затем список читается заново. При перескоке нужного
номера длительность следующего шага уменьшается. Если номер уже в видимом диапазоне,
бот не листает сразу обратно, а пытается прочитать строку на месте.

Номер помогает выбрать строку, в том числе с обрезанным названием. Это только
навигация по интерфейсу. До подтверждения телепорта нужно совпадение полного
назначения в открывшемся окне. Для длинного обрезанного заголовка проверяется полное
имя в описании. Центральное дополнительное подтверждение и проверка прибытия сохранены.
Если подтверждение назначения невозможно, свиток не нажимается по одному номеру.

## Qwen

В присланном журнале v0.12.3 полезных ответов Qwen не было. Нельзя считать его
работающим только по наличию установленной Ollama. Основной поиск ведут миникарта,
распознавание подписи/ромбика, локальные модели поверхности и относительной глубины.

Если /api/chat возвращает пустой ответ, теперь один раз пробуется /api/generate
той же локальной модели. Оба ответа проходят строгую проверку JSON. После трёх
ошибок новые попытки откладываются на минуту; движение не ждёт советника.
CHECK_ANALYZER.bat проверяет связь и формат на синтетическом кадре, не захватывая игру
и не нажимая кнопок. Результат — hybrid_check.json; ошибка — hybrid_ai_error.json
с краткими ответами обоих методов API. Работоспособность вашей Ollama нужно проверить
на вашем компьютере; резервный API не гарантирует исправления серверного сбоя.
