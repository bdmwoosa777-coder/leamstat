# Маленький тестер ЛКМ / ПКМ для Logitech G502 и G700s

## Сначала проверь Windows-методы

1. Останови бота. Распакуй архив в отдельную папку и запусти **START.bat**. Дополнительные Python-пакеты не нужны.
2. Оставь **SendInput / ПКМ**. Встроенную память мыши можно оставить ON. G HUB для этого метода не нужен.
3. Переключись в игру, открой карту, наведи курсор на точку и нажми **F8**. Через 3 секунды тестер отправит один ПКМ. Он не двигает курсор.
4. Проверь, побежал ли персонаж. Вернись в тестер и нажми **«В игре сработало»** или **«В игре не сработало»**.
5. Повтори с **mouse_event** и **PostMessage**. Затем теми же методами можно проверить ЛКМ. **F9 отменяет текущий тест.** Закрытие освобождает собственные нажатия и глобальные F8/F9.

Отдельно физически нажми G-кнопку с ПКМ. Её событие появится в журнале. **mouse_test.log лежит рядом с START.bat**, без вложенных папок. Есть кнопка «Скопировать журнал».

## Отдельный тест G HUB Lua

Этот метод использует G HUB, а не встроенную память. Сначала верни **ON-BOARD MEMORY MODE → OFF**.

1. В тестере нажми **«Скопировать Lua для отдельного тестового профиля»**.
2. Вставь код в отдельный профиль G HUB. Прежний Lua бота сохрани в его игровом профиле. Для возврата к боту потребуется снова выбрать тот профиль.
3. При активном тестовом профиле физически нажми **G9**. В журнале G HUB должна появиться строка `[MOUSE TEST] ARMED`.
4. В тестере выбери **G HUB Lua / ПКМ**, перейди в игру, наведи курсор и нажми F8. Кроме отсчёта, передача Lua-команды занимает ещё примерно 1–2 секунды.

В API Logitech **PressMouseButton(3) — ПКМ**, **(1) — ЛКМ**. Тестер отправляет одиночный клик с отпусканием через 120 мс. У его Lua собственный бинарный канал; он не посылает SOF=3 старому приёмнику бота, поэтому команда теста не должна превращаться в Tab/F/V. Неверная контрольная сумма не выполняет клик. Физический G9 нужен для включения приёмника; программа его аппаратно не нажимает.

## Как понимать результат

- `SendInput` сообщает, приняла ли Windows отчёт. Это не подтверждает, что игра выполнила действие.
- `mouse_event` и успешный `PostMessage` тоже не дают подтверждения от игры. Для PostMessage отправка идёт исходному активному окну; перемещение фокуса не направляет отпускание другой программе.
- `injected=True` означает, что Windows пометила наблюдаемый клик программным. `injected=False` **не доказывает**, что событие аппаратное или принято игрой. Оконные сообщения могут вообще не появляться в таком наблюдении.
- Встроенная память хранит назначения кнопок. Тестер **не умеет программно нажимать произвольную физическую G9 внутри G502/G700s** и не обещает запустить сохранённый аппаратный макрос из Python. Мы проверяем реальные доступные методы, а принятие игрой отмечаешь ты.
- Если игра запущена с повышенными правами, а тестер нет, это может влиять на доставку Windows-ввода. Возвращённая ошибка пишется в журнал; автоматического запроса повышения прав нет.

На G502 и G700s используются те же тесты. Модель мыши тестер автоматически не определяет. Никаких драйверов, HID-подмены, чтения памяти игры и установки ПО в нём нет.

## Проверка

```
python -m unittest test_mouse -q
```

11 проверок прошли, включая три проверки исполнения настоящего тестового Lua через optional `lupa`. Проверены размер INPUT на 64 битах, разные кнопки, одиночное нажатие/отпускание, отмена, освобождение после ошибки, отделение канала бота, ПКМ Logitech=3 и запрет клика с плохой контрольной суммой. `lupa` нужен только для тестов Lua, самой программе — нет.

Живого запуска Windows/G502/G700s/AION2 здесь не было. Наблюдение Windows и отметка пользователя служат диагностикой; автоматического подтверждения из игры нет.
