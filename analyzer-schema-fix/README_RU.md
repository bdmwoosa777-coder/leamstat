# Патч ANALYZER_SCHEMA_FIX для v0.11.2

Закройте бот. Распакуйте все файлы архива прямо в существующую папку v0.11.2
рядом с app.py, с заменой route_analyzer.py и check_analyzer.py.
Затем выполните имеющийся CHECK_ANALYZER.bat. Повторные SETUP, загрузка модели
и замена Lua не нужны. Файлы test_*.py предназначены для проверки разработчиком.

В присланном отчёте модель размещена в VRAM (~3 ГБ), суммарное время запроса
и проверок API — 1,16 с. valid_answer=false вызван проверкой структуры JSON.
Фактический ответ в старом отчёте отсутствует: какие поля отличались, неизвестно.

Изменения: формат ответа ограничен двумя полями route_id/scene через минимальную
схему Ollama. В текст запроса вместо полной схемы включён пример со значениями.
Код продолжает отвергать неизвестные ID и недопустимые поля. Исключение теперь
содержит имена полученных полей. Новый check_analyzer сохраняет фактический
текст ответа и счётчики только для синтетического теста, включая случай отказа.
Изображение, запрос с base64 и игровые ответы в этот отчёт не записываются.

Если valid_answer=true, можно запустить START.bat. Это подтверждает только
правильный формат ответа: оценка игровой сцены и свежесть подсказки проверяются
отдельно. Если valid_answer=false, нужен новый analyzer_check.json: поле
 test_response.content теперь покажет, что именно возвращает модель.

Проверено: 92 теста клиента, диагностики, наземных путей и сцены, OK. Реальный
HTTP-сервер проверяет передачу двухполейной схемы; тест диагностики сохраняет
корректный и некорректный синтетический ответ. Настоящие Qwen/Windows/AION2 здесь
не запускались. Поведение модели на компьютере пользователя ещё не подтверждено.

Патч не меняет сбор, перелёты, сетевой EXE, модели ONNX, настройки и Lua.
Пользовательский отчёт и личные журналы в архив не включены.
