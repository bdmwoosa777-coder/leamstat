# ACore2 GatherScanner v0.8 — встроенная сеть

**CubeRadar больше не нужен.** Захват, сборка TCP и разбор сообщений входят в архив и запускаются вместе с ботом. Выбирать сторонний exe, запускать запись и ждать её завершения не требуется. Npcap остаётся нужен — он у тебя уже работал при записи.

## Запуск

1. Закрой старого бота. Распакуй **весь архив в новую папку**. Внутреннюю папку `native_network` сохрани на месте. Можно перенести `settings_gather.json` и свою `assets/world_map`; старый путь CubeRadar будет проигнорирован. Python, Tesseract и виртуальный Xbox остаются прежними.
2. В игре используй **режим управления 2**. Первый запуск лучше делать стоя на земле, без начатого вручную сбора. Режим 1 в этой сборке отдельно не адаптирован.
3. В G HUB поставь **ON-BOARD MEMORY MODE → OFF** и выбери профиль с **GHUB_GATHER_SCANNER.lua** из этого архива. Если раньше проверял мышь — верни профиль бота вместо тестового. Код Lua прежний; физический G9 включает приёмник.
4. Запусти **START.bat**. Оставь **«Встроенная сеть: подтверждать сбор и удары»** включённой, а **«Только наблюдение»** — выключенной. Нажми **Ctrl+F8**, переключись в игру. **Ctrl+F9 — стоп**.
5. В журнале должна появиться строка **«игровой поток подтверждён, поиск разрешён»**. Отсутствие исходного ID персонажа теперь не блокирует поиск и патруль. Для проверки есть кнопка **«Состояние сети»**.

Go, .NET и отдельную программу захвата устанавливать не нужно. В архив включён готовый внутренний модуль для **64-разрядной Windows**. AionCore не служит источником этого подключения.

## Как работает сбор

- Поиск и наведение пока используют изображение миникарты и названий. Виртуальная A выбирает ресурс; свежий сетевой ответ подтверждает цель.
- Один стартовый **F** запускает игровой автопуть. Повтора F во время подхода нет. Открытие V при подтверждённом застревании может потребовать одного нового F, как раньше.
- Повтор F разрешается после связанных сообщений **собственного** начала сбора. Если исходный профиль персонажа не попал в захват, его ID определяется по текущему выбору ресурса, приватному сообщению окна сбора и однозначному сообщению взаимодействия. Одна чужая попытка рядом, чужой HP или красная точка такого разрешения не дают.
- Между попытками ресурс сохраняется; исчезновение нижнего окна или нулевой выбор сами по себе не закрывают крылья. Три использованные попытки / удаление ресурса завершают сбор.
- Защита реагирует на сетевое попадание именно по своему персонажу; цель моба может быть духом. До определения своего ID эта защита не включается. Урон от падения не считается нападением.
- Серверные heartbeat-сообщения теперь сохраняют актуальность соединения и во время простоя. При задержке более 2.5 с, пропуске TCP или ошибке захвата собственный ввод приостанавливается/останавливается; уже запущенный игрой автопуть может продолжаться.

## Если снова нет действий

Нажми **«Состояние сети»**, затем **«Сохранить журнал…»** и пришли файл. Обычный журнал — **gather.log**, рядом с START.bat. Локальная папка **network_diagnostics** содержит состояние и ошибки внутреннего модуля; полные пакеты/pcap по умолчанию больше не записываются. Ничего автоматически никуда не отправляется.

Отсутствие Npcap, ошибка доступа к адаптеру, завершение модуля и задержка данных теперь выводятся в основной журнал. После смены VPN/игрового подключения может потребоваться остановить и снова запустить бота.

## Что ещё не добавлено

Программный ПКМ на большой карте остаётся нерешённым. Маршруты по сетевым XYZ, новая сетка проходимости и переработка визуального патруля в этом обновлении не добавлены. Бюджет крыльев по-прежнему использует числовую энергию, когда известен её максимум, иначе — прежнее измерение по экрану. Защита поддерживает прямой Hit; отдельный DoT и нападение только на духа без попадания по персонажу пока не добавлены. Неизвестный тип моба не получает разрешение на атаку.

Проверки на записях и ограничения живого тестирования — **VALIDATION_RU.md**. Происхождение открытого кода и лицензии — **THIRD_PARTY_NETWORK.md**. Пользовательских записей и журналов в сборке нет.
