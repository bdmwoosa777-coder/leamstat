# Проверка v0.12.47 WIRE

2517 tests, OK, без пропусков, 175.844 с

Новый test_map_wire47.py проверяет реальный MapKeyWire.send/_toggle,
реальный MapMouseKeys, реальный GHUB_MAP_MOUSEKEYS.lua через Lupa-корутину,
виртуальный Windows keybd_event/GetKeyState и игру с Num Lock = автобег.
ACK берётся из исполнения Lua, а не из заранее успешной заглушки.

Проверены полный PING → M → один числовой ПКМ → M → закрытие транспорта;
маршрут остаётся активен, Num Lock ни разу не нажат, клавиши отпущены.
Проверено воспроизведение нажатий Num Lock прежним передатчиком,
отказ без нажатий при выключенном Num Lock, отказ старого Lua на новом PING,
серия соседних команд, отзыв разрешения до checksum и перед Num5,
подтверждение после отпускания Num5, неподдерживаемые команды.
Контроллер проверяется отдельно: неподтверждённый клик не вызывает импульс
стика; подтверждённый застрявший маршрут ещё можно остановить.

Прежние тесты числового ПКМ обновлены под новый однобитный протокол.
Проверки карты/рельефа, координат/каталога, ресурсов, сети, статистики,
Xbox и защиты выполняются вместе. Исходники и изменения относительно
проверенных v0.12.45 + v0.12.46 проверяются, архив сверяется по байтам/CRC/SHA.
Пользовательские логи, кадры, настройки, приватная память в архив не входят.

Windows/G HUB/AION2 здесь отсутствуют. Это проверка программ и протокола
на имитации клавиатуры/игры, не подтверждение принятого ПКМ живой игрой.
Конкретная привязка Num Lock пользователя по журналу неизвестна.
