# ACore2 GatherScanner v0.9.17 — один клик по ромбику

Ручная проверка F710 выявила разницу: клик по телу ресурса безопасно
повторяется, а клик по ромбику работает как F и может отменить уже начатый
подход или сбор. Прежняя программа считала эти точки одинаковыми.
В этой версии выбран вариант **один клик по ромбику**.

## Изменения

- Первый клик по ромбику уже считается запросом подхода/сбора. Второй
  «активирующий» клик после выбора эфира больше не отправляется.
- При движении к ресурсу повтор по ромбику не разрешается только потому,
  что прошло время, цель выбрана или нет нижней плашки.
- После собственного результата по сети разрешён один следующий клик.
  Его доставка/повтор того же результата/selected=0 не дают ещё один клик.
- Картинка «полоса заполнена» больше не считается окончанием попытки.
  В журнале она ошибочно срабатывала за несколько секунд до результата
  сервера, и последующий A отменял сбор.
- Уже отправленный запрос остаётся ожидающим подтверждения. Если через
  8 секунд нет новой попытки, нижней плашки и подтверждённого прогресса,
  бот может пропустить ресурс вместо остановки всего сканера.
- Если после исчезновения плашки не удаётся получить точку для разрешённого
  восстановления, ожидание ограничено. Старый active не удерживает
  персонажа минуту. Исключение привязано к прежнему ресурсу/попытке;
  новая попытка и реальная нижняя плашка возвращают обычные блокировки.

При появлении незавершённой нижней плашки A и повторное включение курсора
не выполняются. Окончание последней попытки по сети завершает ресурс.
Отсутствие названия/ромбика само по себе не считается исчерпанием.
Общий счётчик чужих сборов не заменяет собственный результат.
Сетевые флаги и числа попыток искусственно не меняются.

Многократный автоматический поиск кликами по телу в эту версию не добавлен:
для него нужно отдельно выделять тело, а не использовать координаты ромбика.
Восстановительный запрос по ромбику без нового собственного результата
запрещён. Если другая цель перехватила выбор, сохраняются проверки её ID.

## Камера, бой и настройки

940 мс остаются значением по умолчанию. Воздушная защита v0.9.16 сохранена:
камера вниз перед Tab, проверка ID ударившего NPC, ограниченный поиск,
возврат к ресурсу после убийства либо отход при неудаче. Обычный сбор не
выравнивает камеру многократно. Контроль энергии и приоритет эфира сохранены.
F в обычном сетевом режиме сбора не используется.

## Запуск

1. Закрой старую программу. Распакуй архив в новую папку, запусти START.bat.
2. Игра — режим управления 2; G HUB — прежний профиль бота, встроенная
   память OFF. Физическая G9 включает приёмник Lua. Lua и сетевой EXE
   остались прежними, переустанавливать их не нужно.
3. Ctrl+F8 — запуск, Ctrl+F9 — стоп. Сеть включена, «Только наблюдение»
   выключено. Наклон 940 мс уже задан в новой папке.

Оставь collection_event_driven включённым: новая политика рассчитана на
этот штатный режим. Явное отключение сохраняет старую диагностическую ветку.

## Диагностика

EMBLEM_ROUTE — первый клик уже запустил подход, второго не будет.
EMBLEM_ONCE — повтор по ромбику отклонён.
COLLECTION_NEXT — клик доставлен, но новое начало ещё нужно подтвердить.
COLLECTION_UNCONFIRMED — ограниченное восстановление завершилось пропуском
цели и поиском следующей. lower=full_hint — только визуальный признак;
он не разрешает следующий сбор. partial/absent описывают реальную панель.

Подробности проверок — VALIDATION_RU.md. Пользовательские журналы, полные
кадры и сетевые захваты в архив не включены и автоматически не отправляются.
Windows/AION2/G HUB здесь не запускались: автоматические проверки
подтверждают условия ввода, а игровой результат требует нового запуска.
