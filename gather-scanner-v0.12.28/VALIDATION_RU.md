# Проверки v0.12.28 FULLVIEW

Полный набор: 1921 tests, OK, без пропусков. Новые сценарии: 16 в test_fullview.py.

Факты из присланных данных:
- qwen_last_view.json: request=16, Invalid confidence, goal_epoch=6,
  goal_bearing=182, ground_routes=[];
- qwen_last_advice.json: другое наблюдение, goal_epoch=5, goal_bearing=194,
  четыре кандидата, успешный ответ confidence=0.64;
- эти файлы не образуют пару «этот кадр — этот ответ»;
- на картинке игровая область существенно закрыта прямоугольниками кода;
- в последнем журнале нет HYBRID_CAMP_EXIT. Почему цветовой ориентир не был
  принят в каждом отдельном кадре, по одному журналу установить нельзя.

Проверяется реальный локальный HTTP и декодирование отправленного JPEG:
один кадр 640x360, видимые верх/лево/право, только нижняя панель скрыта.
Для компакта проверяется сохранение пропорций и крайних пикселей.
Проверка всех изменённых пикселей подтверждает единственный прямоугольник
32–74% по x, 85–100% по y: около 6.3% игрового вида вместо широких блоков.
Отдельная миникарта/чёрное поле снизу и рисование путей отсутствуют.
Модельный промпт не содержит числовых confidence локальных кандидатов.

Настоящий TemporalAdvisor с управляемым клиентом пишет согласованные файлы.
Проверены одинаковые request/captured/image_sha256, хеш фактического JPEG,
ошибка confidence с сохранённым исходным JSON без применения, замена старого
совета при следующей ошибке, отсутствие старого JPEG при ошибке до кодирования.
Время диагностики не прибавляется ко времени инференса. Новая ошибка не
превращается в совет, старый совет не приписывается новому изображению.

На синтетической прямоугольной миникарте 313x207 фиолетовый ориентир в ~50
пикселях от центра не проходит прежний поиск, но проходит явный радиус 65.
Проверяется настоящий HybridGatherEngine: этот ориентир включает выбор
видимого прохода; направление ещё не назначается до появления пути.
Далёкий ориентир не принимается, радиус специального мостика не меняется.
Это проверка условий и цветовой геометрии, не настоящий кадр лагеря.

Три прежние проверки изменены под новую политику изображения: отсутствие
чёрного поля/копии миникарты, сохранение верхнего левого угла и сохранение
того же угла в истории наблюдений. Остальные прежние сценарии сохранены.

Сбор/защита, сеть, карта, Xbox, калибровка, изоляция процессов и веса не менялись.
Порог возраста совета 8 с, confidence>=0.65 и проверка текущего связного пути
не ослаблены. В app.py изменён только номер версии. Файлы диагностики
перезаписываются, сырые пакеты, thinking и новый архив кадров не добавлены.

Модель Qwen и реальная навигация здесь не запускались. Новая подготовка кадра
не доказывает способность модели выбрать ворота или исполнителя пройти их.
Работа автоматического определения лагеря на новых пользовательских кадрах
требует проверки; однозначную причину отсутствия детекции по логу не утверждаем.

Пакет: allowlist из прежнего опубликованного архива, Python/JSON, проверка
дубликатов методов, неизменность весов/бинарников, CRC ZIP, обратное чтение,
SHA256. Публикуются только ZIP, README_RU, VALIDATION_RU и SHA256SUMS в отдельной
downloads-ветке. Новый журнал/JSON/изображения пользователя и runtime-файлы
в публичную сборку не входят.
